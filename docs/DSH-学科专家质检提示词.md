# 学科专家质检（Academic Review）· 实施说明

> 这版取代了之前「课堂术语复核员」的定位：用户要的是**学科专家**，检查笔记里的知识是否符合科学事实，不只是判断替换成不成立。
> 旧的术语复核方案仍保留在 `DSH-纠错自检与术语知识库提示词.md`，作为「知识库反查」的后续扩展，不在本版范围。

## 一、做了什么（v1.6.0）

| 层 | 实现 |
|---|---|
| 模型 | `lib/models/academic_review.dart`：`SubjectCode`（botany / computer_science / law / general）、`AcademicReview`、硬伤 / 逻辑漏洞 / 术语正名三类条目，JSON 双向兼容 snake_case 与 camelCase |
| 服务 | `lib/services/academic_review_service.dart`：`route()` 先判学科（只看前 800 字，`max_tokens=200`），`review()` 交给学科专家（正文上限 8000 字，`max_tokens=3000`） |
| 存储 | `dbVersion` 10→11，新增 `academic_reviews(note_id PK, subject, result_json, created_at)`，一篇笔记一份，重跑覆盖 |
| 界面 | 笔记详情 AppBar 新增 🎓「学科质检」；跑完弹底部面板：硬伤（红）/ 表述不严谨（橙）/ 术语正名（可逐条「替换」，全部替换并可撤销）/ 复习建议（绿）；原文页顶部常驻「上次学科质检：N 处问题 · 查看」 |

## 二、为什么分两跳

路由与质检拆成两次调用：

- 路由只喂 800 字、200 token，成本约 0.0005 元，判错也只损失这一点；
- 质检才喂 8000 字、3000 token，约 0.01~0.02 元。

一次调用同时做「判学科 + 质检」也能跑，但模型会为了自圆其说把笔记硬塞进某个学科。分开之后，路由置信度 < 0.35 直接转 `general`，不硬判。

## 三、学科规则库

`AcademicReviewService.subjects` 里每个学科一条 `rules` 文本，直接拼进专家提示词：

- **botany**：茎变态 vs 叶变态、茎卷须/叶卷须/托叶卷须、同功不同源、芋头是球茎、佛焰苞、捕虫叶触发 vs 消化、地下变态茎的三重适应意义。
- **computer_science**：复杂度、数据结构定义、代码逻辑漏洞、OS 概念（进程/线程、死锁四条件）。
- **law**：法条编号与内容对应、主体/客体、构成要件、程序顺序；只做知识核对，不出法律意见。
- **general**：循环定义、分类标准混用、相关当因果、数据缺单位、类比当论证。

新增学科只需：`SubjectCode` 加枚举值 → `subjects` 加一条规则 → 路由提示词加一行代码。

## 四、JSON 契约

模型输出（提示词里已固定）：

```json
{
  "agent_name": "植物学质检官",
  "summary": "发现 2 处硬伤，3 处表述不严谨",
  "hard_errors": [{"id":1,"error_type":"分类归属错误","original_text":"…","reason":"…","suggestion":"…"}],
  "logic_flaws": [{"id":1,"original_text":"…","reason":"…","suggestion":"…"}],
  "term_corrections": [{"wrong":"…","correct":"…","reason":"…"}]
}
```

程序侧清洗（不是模型自觉）：

- `original_text` 为空 → 丢弃（定位不到就没有展示价值）；
- `term_corrections` 里 `wrong == correct` → 丢弃；
- 置信度不用模型自报，靠路由置信度 + 人工采纳；质检条目不写「置信度」字段，避免伪精确。

## 五、边界与红线

1. **只出结论，不改正文**。术语替换必须点「替换」并二次确认；正文改动走 `PendingFixer`，可撤销。
2. **找不到原文就不报**。提示词要求 `original_text` 原样出现；程序侧只校验非空，不强行定位。
3. **不越界**：不评价排版、不改写段落、不提供法律意见。
4. **失败不降级成假结果**：网络/解析失败直接提示，不返回「看起来像质检」的空壳。
5. **成本可见**：结果面板底部写明「基于笔记文本与学科常识，不替代教材和老师」。

## 六、真实调用记录（2026-11-23，用户提供 Key）

输入：一段 300 字植物学笔记，故意埋 4 个错误（芋头写成块茎/叶变态、茎刺叶刺说成同源、捕虫叶触发机制说成消化、佛焰苞写成花瓣）。

| 项 | 结果 |
|---|---|
| 路由 | `botany`，置信度 0.98，理由「内容为植物茎与叶的变态类型及适应意义」 |
| 植物质检（初审） | 5 处硬伤 / 1 处不严谨 / 2 处术语正名；4 个埋的错误全部抓到，且 `original_text` 都能回到原文 |
| 耗时 | 路由 + 质检合计约 6–9 秒（两次独立调用） |
| 报错 | 无（网络、鉴权、JSON 解析均正常） |

**抓到的典型问题**：

- 「芋头是典型的块茎，属于叶的变态」→ 指出芋头是地下球茎、属茎的变态，具环状节与退化叶；
- 「茎刺与叶刺是同源结构」→ 指出是同功不同源；
- 「捕虫叶靠消化腺分泌蛋白酶来触发」→ 区分触发（刚毛）与消化（消化腺）；
- 「红掌花序外面的保护结构叫花瓣」→ 佛焰苞；
- 术语正名：花瓣→佛焰苞；芽眼（用于芋头）→环状节与退化叶。

**发现的误报（如实记录）**：

「球茎（如荸荠）有明显的节和节间，节上有膜质鳞叶」这句本身是对的，两次运行都被误判为硬伤，且两次给的理由不同（一次说该把芋头并进来，一次说这是根状茎）。说明**光靠提示词约束不住「相邻错误带偏」**，这类误报要等知识库/教材检索接上、给模型可核对的依据才能压下去。

**二审（v1.7.0，单句复核）**：整段质检先把 5 条候选交上去，再对每一条用「单句审稿专家」提示词逐句复核（上下文隔离 + 宁可不报不许误报）。结果：

- 那条误报被挡掉，最终 4 处硬伤、0 处误报；
- 4 条都带上 `evidence`（教材式定义）并标记 `verified=true`；
- summary 同步改为「复核后保留 4 处硬伤…（初审 5 处，已剔除单句复核不成立的误报）」，不会出现「说 5 处、只列 4 条」；
- 耗时 12–13 秒（路由 1 次 + 整段 1 次 + 单句复核 5 次），比单段质检多 3–6 秒，成本增加约 0.005–0.01 元。

**三审（v1.8.0，逐句全审）**：增加「每句都判」模式。12 句的样例，4 路并发约 11 秒：

```
逐句审阅 12 句：4 处硬伤、0 处表述不严谨
```

4 处硬伤与预埋错误完全一致，误报 0 条；`warning` 级会进「表述不严谨」，`fatal_error` 级进「硬伤」。超过 60 句只审前 60 句并在 summary 里写明，不静默截断。

两种模式的分工：
- **快速质检**：整段找候选 + 复核候选（约 12 秒，5~8 次调用）；
- **逐句全审**：每句一次调用（12 句约 11 秒，60 句约 20 秒），漏报最少、成本最高。

结论：**整段质检负责找候选，单句复核负责判真假**，两层配合后精度从 4 真 + 1 假变成 4 真 + 0 假。单靠提示词纪律（v1.6.1 加的那条）压不住误报，必须改变判定粒度。

## 七、知识库依据（v1.9.0）

`RAG_EVIDENCE` 不再留空。事实来源目前有两处：

1. **本节术语表**（`TerminologyPack`）：`term + 中文释义 + 常见误听形式`；
2. **本课程已确认的知识库词条**（`wiki_entries`，`status=confirmed`）：`term + definition`。待确认词条不收——用没验证的东西验证别人，等于把错误放大。

每条待审句按「二字组重叠」挑前 3 条相关证据，塞进提示词的 `{{RAG_EVIDENCE}}`，格式 `【知识库】芋头：地下变态茎中的球茎…`。

**接地校验**（程序侧，不是模型自觉）：

- 模型判 `fatal_error`、但我们给了证据、它的 `evidence` 里却一个二字组都没引到 → 自动降为 `warning`（存疑），并在 summary 里记「N 处因未引用知识库依据降为存疑」；
- 证据池为空时照常判，但 summary 会写明「本次无知识库依据，结论仅凭模型知识」；
- 引到了才留在硬伤里，并原样展示 `evidence`。

真实运行（12 句、5 条知识库证据）：仍为 4 处硬伤、0 误报，4 条都引到了提供的条目，summary 追加「已提供 5 条知识库依据」。

### 向量检索（v2.0.0）

依据不只靠「二字组挑 3 条」，另加了一层本地向量索引：

| 项 | 做法 |
|---|---|
| 检索模型 | **本地字符 n-gram 哈希向量**（1/2/3-gram 加权 → 512 维，L2 归一化）。不连网、不把正文送出去 |
| 语料 | 本课程已确认的知识库词条 + 同课程笔记的句子（按 `AcademicReviewService.splitSentences` 切），上限 800 条 |
| 检索 | 余弦相似度线性扫描，每句取 top 2（阈值 0.12），再与术语表证据合并去重，总计 3 条 |
| 接入 | `reviewAllSentences(retriever: ...)`；UI 在 `_buildEvidenceIndex` 建索引 |

**为什么不上语义模型**：App 承诺正文不出本机；教材正文也还没有，训不出像样的语义空间。字符向量在这个规模下够用——它抓字面重叠，抓不到「块茎 vs 地下茎」这种同义改写，这是已知短板，不是 bug。

**换语义模型的接口**：只需替换 `LocalEmbedder.embed()` 的实现（比如调 bge-m3 拿 1024 维），`EvidenceIndex` 与检索逻辑不用改。真要上云 embedding，得先改隐私条款。

### 联网检索维基（v2.2.0）

按「先查后判」实现：

- 新增 `WikiSearchService`：调中文维基 MediaWiki API（`generator=search` + `extracts`），返回 `title/extract/url`；
- 每句审阅时，若开关开启，先检索这句（截到 60 字）的公开条目摘要，作为 `【维基百科】标题：摘要` 塞进 `RAG_EVIDENCE`；
- 提示词加规则 0：**先查后判**，`evidence` 必须摘抄检索结果原句，搜不到证据只能判 `warning`/`correct`；
- 程序侧沿用接地校验：`evidence` 与提供的依据无二字组重叠 → 自动降 `warning`；
- 网络失败/超时（维基在大陆网络常不可达）返回空列表，质检退化为只用本机知识库，不阻塞、不报错。

隐私：免责声明升到 **1.1**（2026-11-23），新增「质检的联网检索（维基百科）」条款，写明只发送待查术语、不发送整篇笔记；设置里可随时关闭（`wiki_search_enabled`，默认开）。

**未能验证**：本机 `curl zh.wikipedia.org`、`api.wikimedia.org`、`zh.m.wikipedia.org` 全部超时（`http=000`），所以真实检索链路没跑过；单测用注入的假响应覆盖解析与降级。

### 实体书怎么办（v2.1.0）

用户只有实体书，没有教材正文。两条路：

| 路径 | 状态 |
|---|---|
| **教材摘录**（手抄/拍照后系统识字，粘贴入库） | 已实现：设置 →「教材摘录（质检依据）」，按课程 + 章节存原文，进向量语料，来源标「教材摘录」 |
| **拍照 OCR 直接入库** | 未做：需要相机权限、图像预处理和一个视觉模型（含费用与隐私条款变更），属于独立一轮 |

摘录不需要整本录入：一章挑三五句最常考的定义即可。`textbook_passages` 表（v12）只存用户主动给的文本，不自动生成。

**边界**：这层依据是「术语表 + 知识库 + 同课程笔记 + 教材摘录」，在没有摘录时仍不是教材原文——教材库目前只有目录表（`textbooks/chapters/sections`），没有正文。要让 `evidence` 真正引教材原话，还得先把教材正文入库或接向量检索。
