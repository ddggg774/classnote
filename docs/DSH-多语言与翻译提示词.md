## 一、背景（给人看）

现在这个 App 是纯中文课堂的：转写出来是中文，纠错按同音字/拼音改，总结按九段式写中文，术语表按中文课程生成。到了外语课，这套东西会同时坏掉三处——

1. **纠错会把外语改坏。** 纠错提示词是照着「同音字、平翘舌、拼音」写的，遇到英文/日文，模型很可能"顺手翻译"或者把词改成中文，比不改更糟。
2. **总结读不懂。** 九段式提示词假定输入是中文，输出也要求中文，外语课的笔记会变成机翻味的转述。
3. **学生真正需要的是对照。** 外语课的价值不在"翻译成中文"，而在**原文 + 译文逐句对照**——回听时能对上原话，复习时能核对术语。

目标：给外语课一条完整的链路——

```
录音 → 外语转写（原文完整保留）→ 语言适配的纠错 → 逐句翻译（原文/译文对照）
     → 双语总结（术语首次出现带中文释义）→ 检索与 Wiki 同时认两种语言
```

三条红线：

1. **翻译只翻语言，不许改事实。** 不增、不删、不合并句子、不润色。原文永远是主语，译文是叠加物。
2. **原文必须完整保留。** `transcript` 存 ASR 原文，翻译单独存；任何时候删掉译文，笔记还能看。
3. **不支持的语言不许假装支持。** 硅基流动的识别接口**没有 language 参数**（已核对：只有 `file` 和 `model`），语言只能靠模型自己判断。所以"支持哪些语言"必须用真录音实测过再写进界面，不能列一堆语言让用户试。

项目路径：`E:\Downloads\classnote`

### 当前代码现状（已核实，不要重新猜）

**语音识别接口的能力边界**（这条决定整个方案）：

```dart
// cloud_asr_service.dart:609-614
final request = http.MultipartRequest('POST', uri)
  ..fields['model'] = model
  ..files.add(await http.MultipartFile.fromPath('file', filePath, ...));
```

请求体**只有 `file` 和 `model`**，没有 `language` / `prompt` / `hotwords`。语言无法通过参数指定。

**两个可选识别模型**（`lib/config.dart:32-44`）：

| 值 | 说明 |
|---|---|
| `FunAudioLLM/SenseVoiceSmall` | 默认，免费；官方支持中/粤/英/日/韩（以模型卡为准，需实测） |
| `TeleAI/TeleSpeechASR` | 另一个中文识别模型，中文课对比用 |

**纠错是中文专用的**：`lib/services/transcript_corrector.dart` 与 `lib/agent/correction_agent.dart` 都是 A/B/C 三档 + 「同音字 / 拼音 / 平翘舌 / 专业术语」的规则，提示词里写死了「把听错的词还原成老师实际讲的内容」——在外语课里这句话会诱导模型改写甚至翻译。

**术语表**（`terminology_service.dart:80`）：`prepare(courseName, topic, material, knownTerms)`，提示词全中文，产出中文术语 + 常见误听形式。

**总结**（`ai_service.dart`）：`summarize(transcript, {level, courseName, template})`，九段式提示词全中文；`StudySummary.detailMarkdown` 是唯一的正文，没有第二语言版本。分块阈值 `chunkChars = 8000`（按中文估的）。

**笔记表**：`dbVersion = 9`，`notes` 有 `transcript / summary_json / terminology_json / course / template_id / textbook_id / chapter_no / chapter_title / section_no / section_title`，**没有语言字段，也没有译文列**。

**检索**（`search_index.dart`）：中文 bigram + 英文整词小写 + 前缀匹配，英文已经能搜；但没有"译文"这一路。

**设置页**：有 ASR 模型选择、播放档位、技能开关；没有语言相关设置。

### 硬约束

1. **外语课上不许让纠错改语言。** 纠错只允许做「拼写纠正、专名大小写、明显同音误听」，**禁止把外语词改成中文、禁止意译、禁止合并句子**。做不到就标待确认，别改。
2. **翻译必须逐句对照，行数必须能校验。** 整段翻译一定会合并句子，对照就废了。要求「一句一行、带行号」，程序校验行数与输入句数一致；不一致就丢弃重译一次，仍不一致则降级为整段翻译并标「无法逐句对照」。
3. **语言支持必须实测后再写进界面。** MVP 只承诺中 / 英 / 日 / 韩；法语、德语、西语等**在界面上明确标「未验证，可能不可用」**，不许暗示支持。
4. **中文课行为必须零变化。** 所有新增逻辑默认 `language = zh` 走原路径；改完要能证明「中文课的提示词与今天逐字一致」。
5. 不引入新的第三方服务：翻译走现有 DeepSeek 通道（纯文本），不加机器翻译 API。
6. 分阶段交付，每阶段 `flutter analyze` 零告警 + 全量测试 + 打包 APK + git 提交。

### 需求定义

#### 一、语言设置与存储

**字段**：`notes.language`，BCP-47 简写（`zh` / `en` / `ja` / `ko`），默认 `zh`。

**入口**：
- 录音页：课程选择器旁边加「这节课的语言」，默认为中文；选课程后可自动带出该课程上次用的语言（先做"最近一次"，不做复杂配置）。
- 设置页：全局默认语言（新建笔记时用）。

**界面诚实**：语言旁边写一行小字「识别语言由模型自动判断，无法指定」，别让用户以为选了语言就影响识别。

#### 二、转写与纠错的语言适配

| 语言 | 纠错策略 |
|---|---|
| 中文 `zh` | 完全保持现状（A/B/C 三档、同音字规则） |
| 英/日/韩 | 只做三类：拼写错误、专名大小写、明显同音误听；**禁止改语言、禁止意译**；B 类一律只标待确认 |

实现上不要复制一份提示词了事——把「能否修改」的判定写死在提示词里，并加一条**可执行护栏**：改后的词必须与原文同语言（用 Unicode 字符集粗判：拉丁/假名/谚文/汉字），跨语言改写直接丢弃并记日志。

术语表：
- 非中文课，术语用**原文语种**（如 `pinnately compound leaf`），同时给中文释义；
- `knownTerms` 传「原文 + 中文」成对的形式；
- 误听形式按外语的形近/音近生成（不要套拼音规则）。

#### 三、翻译模块

新增 `services/translation_service.dart`：

```dart
Future<TranslationResult> translate({
  required String text,
  required String sourceLang,   // en / ja / ko
  String targetLang = 'zh',
});
```

**流程**：

1. **切句**（纯 Dart，可单测）：
   - 英语：`. ! ?` 结尾，保护 `Mr.` `Dr.` `e.g.` `i.e.` `etc.` 等缩写不要断
   - 日语：`。！？`
   - 韩语：`. ! ?` 与 `다.` 结尾
   - 中文：`。！？`（保持现有）
2. **逐句翻译**，输出 JSON：

```json
{"pairs":[{"i":1,"src":"...","dst":"..."},{"i":2,"src":"...","dst":"..."}]}
```

3. **校验**：`pairs.length == 句子数`，且每句 `src` 归一化后能在原文对应位置找到（顺序 + 内容双校验）。不通过 → 重试一次；再不过 → 整段翻译 + 标「无法逐句对照」。
4. **存储**：`notes.translation_json`（v10 加列），结构里带 `sourceLang / targetLang / createdAt / mode(per-sentence|whole) / pairs`。
5. **失败语义**：翻译失败不改原文、不阻塞录音；详情页显示「未翻译」，可手动重试。

**详情页 UI**：
- 原文 Tab 顶部加「对照」开关：开 → 句子级上下对照（原文一行、译文一行、可点句子回听）；关 → 还是纯原文。
- 译文可编辑（本地），改完标 `edited`，不自动重跑翻译。
- 原文被编辑过 → 译文标「可能已过期，可重新翻译」。

#### 四、双语总结

外语课总结支持三种模式（设置里选，默认「中文总结 + 术语保留原文」）：

| 模式 | 说明 |
|---|---|
| `zh` | 中文总结，术语第一次出现写成「中文（English）」 |
| `src` | 用原文语言写总结（适合语言课本身要练表达） |
| `bilingual` | 中文为主，关键定义/例题附原文引用 |

提示词注入：
- 明确告知「输入是 $sourceLang 课堂转写（可能夹中文解释）」
- 术语格式规则：`细胞壁（cell wall）`
- 硬约束：**总结里不许出现原文没有的内容**；夹杂中文解释时如实保留「老师说：…」

实现：`buildPromptForLevel` / `buildPrompt` 增加可选 `language` 与 `summaryLanguage` 参数，默认 `zh` 走原字符串（保证中文课逐字不变）。

#### 五、检索与 Wiki

- **检索**：`IndexDoc` 加 `translation` 字段（权重 1，与原文同级或略低），译文也进 bigram/整词索引——学生用中文关键词也能搜到外语课的笔记。
- **Wiki**：`term` 存原文（`cell wall`），`definition` 存中文；唯一键仍是 `course + term`。外语课与中文课的同名词条不互相干扰（课程不同）。
- **RAG**：回答带出处；跨语言回答时标注「原文为英文，以下为译文」。

### 技术判断与风险

1. **ASR 的多语言能力是最大不确定项。** SenseVoiceSmall 官方支持中/粤/英/日/韩，但课堂场景（口音、混说中文解释、远场）没验证过。**先拍三段真实录音**（英语课 5 分钟、日语课 5 分钟、英中混说 5 分钟）跑转写，看错词率再决定对外承诺哪些语言。TeleSpeechASR 是中文模型，外语课别选它。
2. **切句质量决定对照表能不能用。** 英文缩写断句（`Mr. Smith`）、日语没有空格、韩语敬语结尾，都要单独处理；切句器必须是纯函数并且有测试，别藏在提示词里。
3. **翻译的忠实度靠结构约束，不靠"请忠实翻译"。** 一句一行 + 行数校验 + src 回查，是唯一能自动发现的编造方式。
4. **纠错在外语下更危险**：模型很容易"顺手把整句改写得更通顺"。护栏要可执行：改动跨度、语言字符集、原文可定位。
5. **成本**：翻译一节课 ≈ 全文输入 + 全文输出，按 40 分钟 7000 字算约 **+0.08–0.12 元/节**；双语总结再 +20–40%。对"一节课一毛"的现状是可接受的，但要写进设置页的说明里。
6. **数据迁移**：v10 加 `language` / `translation_json` 两列，可重入；老笔记默认 `zh`，不迁移数据。
7. **中文课回归**：新增参数一律可选，默认走旧路径；测试里加一条「中文课提示词与 v1.1.0 逐字一致」的快照对比。

## 三、需要你拍板的几个问题

1. **MVP 语言范围**：只做英语，还是英语 + 日语？三语都上风险大（尤其日语切句和识别质量）。我建议**先英语**，日语作为第二个验证目标。
2. **总结默认语言**：中文总结（术语保留原文）、原文语言总结、还是双语？我建议默认「中文 + 术语保留原文」——外语课的学生最终还是要用中文理解和复习。
3. **对照的展示方式**：双栏（左原文右译文）还是逐句上下？手机竖屏我建议**上下逐句**，双栏在 6 寸屏上每边太窄。
4. **用户改了原文之后**：译文标「可能过期」让他手动重翻，还是自动重翻（花钱）？我建议标过期 + 手动。
5. **术语表**：外语课要不要同时生成"中文释义"？我建议要，否则复习时还是看不懂。
6. **成本**：翻译让每节课从约 0.1 元涨到约 0.2 元，能接受吗？如果不能，可以只翻"总结用到的段落"，不做全文对照。

## 四、一句话

中文课的链路是"听懂老师说了什么"，外语课还得再往前一步——"这句话用中文怎么说，用原文又长什么样"。这两件事必须分开存，否则学生永远在猜哪句是老师原话。
