## 关键设计决策（为什么这么做）

**1. Agent 层用 Dart 写在 App 内，不是 Python 服务器**
现有 App 直连 DeepSeek，加服务器会退化体验。Function Calling 本质是 HTTP+JSON，用现有 `http` 包即可，不引框架。

**2. Agent 只管文本处理流水线**
`transcribe` 接收**已切好的音频片段**。录音、切片、中断恢复、前台服务仍归 `RecordPage`，那部分已验证过，不塞进 Agent 循环冒险。

**3. 模板只替换「输出结构」**
`_detailSystemPrompt` 拆成五个常量（header/铁律/整理要求/九段式正文/导图规范）。铁律与整理要求一字未改、所有模板共用。若把整个 prompt 当模板，自定义模板等于让用户重写防编造底线。

**4. 内置模板走老路径，零回归**
九段式与速览继续走 `buildPromptForLevel`，产出与改造前逐字一致；只有新模板走 `_buildFromTemplate`。

**5. 不用 FTS5**
`sqflite` 走 Android 系统 SQLite，FTS5 需 `SQLITE_ENABLE_FTS5`，厂商 ROM 会裁。改用普通表自建 bigram 倒排，100% 可用。

**6. Wiki 冲突不覆盖**
主定义保留最早抽取那版，新说法存 `altDefinition` 供用户裁定。自动“取最新”是替用户做学术判断。

**7. 技能 = 提示词片段 + 工具暴露，两者同时收窄**
只藏工具，模型会困惑；只藏提示词，模型照样调。真实日志证明生效：
`✗ tool:summarize → 错误：不存在名为 summarize 的工具`

**8. 画布不用 InteractiveViewer 管手势**
它内部的 pan/scale 会抢走父层 `onTapUp`。手势识别器放它**内部**，坐标天然正确。

## 已知坑（踩过的，别重复踩）

1. **`TestWidgetsFlutterBinding` 会把 HTTP 拦成 400** → 服务类需 `apiKeyOverride` 注入 Key
2. **`TerminologyService` 读 Key 依赖 SharedPreferences** → 测试会抛错，同上
3. **Gradle 9.5 移除了 `Project.exec()`** → 第三方 gradle 脚本用它就挂，改用 `ExecOperations`
4. **原生编译依赖先验证再承诺** → RNNoise 那次三个障碍叠加（cargokit / NDK 29 / 无 Rust），最后卡在 Windows 开发者模式未开导致无法建 symlink
5. **`showDialog` 返回后不能立刻 dispose controller** → 关闭动画期间 TextField 仍引用它，用 `addPostFrameCallback`
6. **LLM 输出分档别用字数比例** → 按“允许出现哪些章节”白名单控制
7. **`FloatingActionButton.extended` 没有 `onLongPress`** → 改点击弹面板
8. **长异步请求别把整页换 spinner** → 会清掉其他 Tab 的编辑内容
9. **`Flutter` 3.50 起 `package:flutter/material.dart` 已废弃** → 用 `package:material_ui/material_ui.dart`
10. **子节点布局要算自己半宽**：`childX = parentX + nodeWidth + gap`

→ MindGraph → 落库 → [搜索索引 | Wiki词条 | 画布渲染 | 待确认清单]
