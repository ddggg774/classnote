## 1. 现状核实（逐文件，带行号）

### 1.1 教材配置：只有元数据，硬编码

`config.dart:57-77` —— 三本教材只有 `course / book / author / publisher` 四个字段，是 `const` 常量。`textbookOf()` 用 `contains` 双向模糊匹配，`textbookLine()` 拼成一句提示词文本。

**含义**：教材不能增删改、不能多个版本并存、没有目录。要支持「教材库」必须从常量升级成数据表，`AppConfig.textbooks` 降级为**首次启动的种子数据**。

### 1.2 笔记表：没有位置字段

`db_service.dart:33` `dbVersion = 7`；`notes` 建表语句在 `75-87` 行，列是 `id / title / transcript / summary_json / created_at / duration / status / terminology_json / course / template_id`。

**没有** textbook / chapter / section。

### 1.3 术语缓存：表结构早就够用

`db_service.dart:136-149` `terminology_cache(cache_key, course, chapter, pack_json, updated_at)`，键是 `course|chapter`（`terminology_store.dart:43-44`，两边 `trim` 后拼接）。

**含义**：这张表不用改。前端只要保证「预生成」和「纠错现场生成」传进 `put/get` 的字符串**逐字一致**，命中率立刻从 0 变成 100%。

### 1.4 纠错子 Agent：参数通了，但没接线

- `correction_agent.dart:114-157`：`lookup_terminology(course, chapter)` → 先查 `TerminologyStore.get` → 未命中才 `prepare(topic: chapter)` → 成功后 `put`。
- `correction_agent.dart:144-147`：`prepare` **只传了 `courseName` 和 `topic`，没传 `material`**（教材名/编者/出版社），提示词里「教材/PPT 标题」这一栏一直是空行。
- `correction_agent.dart:50,62`：`presetPack` 是现成的注入点（外部直接塞一份术语包，跳过查库与生成），但全项目没人传。

### 1.5 录音页：课程有了，位置没有

- `record_page.dart:48` `String? _course`，`586-631` 是三门课的 `ChoiceChip` 选择器 + 自定义。
- `record_page.dart:310`：`chapter: ''` —— **硬编码空串**。
- `_persistDraft`（117-147）、`_saveAgentResult`（417-455）、`_finishAndSave`（536-579）三条落库路径都只写 `course`。
- `_loadDraft`（78-86）只恢复 `title / course / transcript`。

### 1.6 总结提示词：只有教材名，没有位置

`ai_service.dart:261-265` `_textbookBlock(courseName)` 调 `AppConfig.textbookLine()`，拼进 `buildPromptForLevel` / `buildPrompt`。章节信息完全没有入口。

### 1.7 检索索引：不认章节

`search_index.dart:72-86` `IndexDoc` 只有 `noteId / title / course / transcript / summary`；`search_terms(term, note_id, field, freq)` 也没有章节列。

**含义**：想"按章节过滤检索结果"，最省事的做法不是改倒排表，而是先按 `notes` 表的位置字段过滤笔记 ID 集合，再在结果里筛。改造量差一个量级。

## 2. 数据结构设计

### 2.1 三层拆开，不拼字符串

```dart
class Textbook {
  final String id;          // uuid
  final String course;      // 课程名，与 notes.course 同一套写法
  final String title;       // 「植物学」
  final String edition;     // 「第三版」
  final String author;      // 「方炎明 主编」
  final String publisher;   // 「中国林业出版社」
  final String year;        // 可空
  final String isbn;        // 可空
  final String tocSource;   // 'manual' | 'pasted' | 'none'
  final DateTime? tocUpdatedAt;
}

class Chapter {
  final String id;
  final String textbookId;
  final String no;          // 「第五章」——原文写法，不规范化
  final String title;       // 「被子植物」
  final int sortOrder;
}

class Section {
  final String id;
  final String chapterId;
  final String no;          // 「第二节」
  final String title;       // 「木兰科」
  final int sortOrder;
}
```

**为什么章号存原文**：老师嘴上说的是"第五章"，教材印的也是"第五章"，界面照抄最省事；规范化成 `5` 之后要显示得反查一次，还会把「上篇/下篇」「附录」这类结构吃掉。排序靠 `sort_order`，不靠解析 `no`。

**为什么章、节分两张表而不是一张自引用**：需求里明确是两层（章 → 节），两张表代码最直白、测试最好写。代价是"篇"这一层放不下——见第 6 节待决策项。

### 2.2 运行时位置对象（不落库，只在页面间传）

```dart
class CourseLocation {
  final String course;
  final Textbook? textbook;   // 没选教材时为 null
  final Chapter? chapter;
  final Section? section;

  /// 缓存键与提示词里统一用这一个字符串
  String get chapterKey => [chapter?.no, chapter?.title, section?.no, section?.title]
      .where((e) => e != null && e.isNotEmpty).join(' ');

  /// 顶部常驻显示：「植物学（第三版）· 第五章 被子植物 · 第二节 木兰科」
  String get displayLine => ...;

  /// 给 prepare(material:) 用：「植物学（第三版），方炎明 主编，中国林业出版社」
  String get materialLine => ...;
}
```

**关键约定：`chapterKey` 是唯一真值。** 术语缓存、提示词、笔记字段全部从它派生，不允许各处自己拼。这是防止"填了位置但缓存永远不命中"的唯一办法（见风险 R1）。

### 2.3 `AppConfig.textbooks` 的处置

不删。改成"种子数据"：

- 首次打开数据库且 `textbooks` 表为空时，把这三条写进去（保留现在的书名/编者/出版社原文）；
- 之后一切读写走数据库；
- `AppConfig.textbookOf()` / `textbookLine()` 保留给**没有教材记录时的降级路径**（老笔记、自定义课程名），避免大面积改动现有提示词代码。

### 5.1 缓存的唯一正确接法

`chapterKey` 三个人用同一份：

```
预览生成  TerminologyStore.put(course, location.chapterKey, pack)
纠错查表  TerminologyStore.get(course, location.chapterKey)
提示词     「章节主题：${location.chapterKey}」
```

**不能让模型自己决定 chapter 字符串**。现状是模型调 `lookup_terminology(course, chapter)` 时自己填章节名——它会写成「第五章 被子植物」还是「被子植物」全看当时发挥，缓存键必然对不上。两处收口：

1. `ClassroomRequest.chapter` 传固定值，并在任务提示里写明"章节名必须原样使用"；
2. 更可靠的一条：课前预生成成功后，把包直接当 `presetPack` 注入 `CorrectionAgent`，`lookup_terminology` 第一优先级就命中，**根本不走字符串匹配**。

两条一起做，缓存命中才有保证。

## 6. 目录解析器设计（第二阶段核心）

### 6.1 先正则，再模型，模型只许重排

`services/toc_parser.dart`（纯 Dart、不依赖 Flutter，便于单测）：

```dart
class ParsedToc {
  final List<ParsedChapter> chapters;
  final List<String> droppedLines;  // 无法归属的行，界面上要如实提示
}

class ParsedChapter {
  final String no;      // 「第五章」
  final String title;   // 「被子植物」
  final List<ParsedSection> sections;
}
```

**正则覆盖（第一优先级）**：

| 形态 | 例子 | 正则要点 |
|---|---|---|
| 中文章号 | 第五章 被子植物 | `第[一二三四五六七八九十百零]+章` |
| 阿拉伯章号 | 第5章 / 5. 被子植物 | `第\d+章` / `^\d+[.、]` |
| 中文节号 | 第二节 木兰科 | `第[一二三四五六七八九十百零]+节` |
| 数字节号 | 5.2 木兰科 / 5.2.1 | `^\d+\.\d+(\.\d+)?` |
| 顿号编号 | 一、木兰科 | `^[一二三四五六七八九十]+、` |

**归属规则**：章行开新章；节行挂到"最近的章"；章之前出现的节行 → 计入 `droppedLines`，不猜。缩进只作辅助信号（有缩进且无编号的行视为上一节点的续行拼进标题）。

### 6.2 模型兜底的行级校验（防编造的可验证做法）

模型返回的每一行，做三步归一后必须能在用户原始输入里找到：

```
去掉空白 → 去掉标点 → 统一全角/半角 → contains 判断
```

找不到的行**直接丢弃**并计数，界面提示「丢弃了 N 行无法对应的内容」。这比在提示词里写"不要编造"可靠一个量级（提示词文档技术判断第 1 条已明确）。

### 6.3 空目录的诚实表达

解析出 0 章时，**不写入数据库**，保留上一次目录（如果有），提示"没有识别到章节，请检查格式或改用手动录入"。`toc_source` 保持原值，别把 `pasted` 写上去假装成功。

### 6.4 测试清单（第二阶段）

- 中文章号 / 阿拉伯章号 / 混合编号 / 缩进续行 / 章前出现节 / 空行与页码混排 / 全角空格 / 超长目录（200+ 行性能）
- 模型兜底：编造行被丢弃、只重排不改字、返回非法 JSON 时降级为正则结果
- CRUD 往返：建教材 → 录目录 → 重启读回（`sqflite_common_ffi` 真实 SQL）
- 种子数据：空库首启灌三本；已有数据时**不重复灌**

## 9. 需要拍板的六个问题

1. **章节层级**：只做两层（章 → 节），还是预留三层（篇 → 章 → 节）？
   两层简单；三层要在表里加 `parent_id` 或再拆一张表，交互也要多一级。我的建议：**两层**，篇/附录这类行在第一版计入"无法归属"并提示。
2. **教材种子**：空库首启自动灌现有三本元数据（书名/编者/出版社），还是完全让用户自己建？
   我的建议：**灌**，但只灌元数据，`toc_source = 'none'`，界面上明确"未录入目录"。
3. **笔记位置可否事后修改**：详情页是否需要「修改位置」入口（选错了能改回来）？
   我的建议：**要**，第三阶段顺手做，一个弹窗复用 `location_picker`。
4. **RAG 按章节过滤**：第一版做还是不做？
   我的建议：**先不做**，等真有章节数据了再加 `search_service` 的可选过滤参数；现在做等于给空数据写代码。
5. **Wiki 章节出处**：第一版加 `wiki_sources` 两列还是延后？
   我的建议：**第一版加**，成本就是两列 + 抽取时读 `note` 字段，展示很轻，但对"复习到某章时找词条"有用。
6. **课前预生成术语表**：默认开还是默认关？
   我的建议：**默认关**，位置选定后弹一次"要现在准备好术语表吗（约一次调用）"，用户同意再跑。静默花钱比慢更让人不舒服。
