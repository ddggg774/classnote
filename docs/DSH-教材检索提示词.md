## 一、背景（给人看）

你要的功能是：**录音之前**先定清楚这节课讲哪本教材、第几版、谁编的、哪个出版社、第几章第几节。

这不只是加个输入框。它解决三个现存的真问题：

**1. 现在教材信息只有"书名 + 出版社"，没有章节**

`AppConfig.textbooks` 里三本教材只有：课程名、书名、作者、出版社。没有章节目录。所以「这节课讲木兰科」这件事，系统完全不知道对应教材第五章第二节。

**2. 术语表本来该用上章节信息，但一直是空的**

`TerminologyService.prepare()` 的签名是：
```dart
prepare({required String courseName, String topic = '', String material = '', String knownTerms = ''})
```
`topic`（章节主题）和 `material`（教材/PPT标题）**两个参数一直没人传**——因为录音页没有地方填。术语表因此只能按"课程名"猜，粒度太粗。

**3. 课前准备这个窗口现在是浪费的**

你打开 App 到按下录音之间有一段空档。这段时间正好够把"今天讲哪一节"定下来，让后续所有环节（术语表、纠错、总结、Wiki 归类）都拿到准确的上下文。现在这段空档什么也没做。

**一个必须写死的红线**：教材目录**绝对不许让模型生成**。章节号编错了（比如把"第五章第二节"说成"第六章第一节"）比没有更糟——它会一路污染术语表、纠错和总结，而且用户很难发现。

### 硬约束

1. **教材目录绝不许由模型生成。** 这是这个功能最重要的一条。
   模型只能做"把用户提供的目录文本整理成结构化数据"，
   **不能凭空写出章节号、章节名**。用户没提供目录就宁可留空，
   界面上明确显示「未录入目录」，而不是猜一个。
   理由：章节号编错会一路污染术语表、纠错、总结，用户很难发现。

2. 保留现有已跑通的功能，不要推倒重写。先读代码、列改造点，确认后再改。

3. 不引入外部平台或框架。涉及原生编译的依赖先验证再承诺（这台机器上踩过 RNNoise 的坑：Gradle 9 移除了 `Project.exec`、缺 NDK 29、无 Rust 工具链）。

4. 优先纯 Dart 方案。

5. 分阶段交付，每阶段 analyze 零告警 + 全量测试通过 + 打包 APK + git 提交。

### 需求定义

#### 一、教材库（比现在多什么）

现在的教材只有四个字段。要扩展成：

```
Textbook {
  id, course,                  // 课程名，用于和笔记关联
  title,                       // 书名，如「植物学」
  edition,                     // 版次，如「第三版」
  author,                      // 编者，如「方炎明 主编」
  publisher,                   // 出版社，如「中国林业出版社」
  year,                        // 出版年（可选）
  isbn,                        // ISBN（可选，用于唯一标识版本）
  tocSource,                   // 目录来源：manual / pasted / None
  tocUpdatedAt,                // 目录最后更新时间
}
```

注意用户说的「出版人」可能指**编者**也可能指**出版社**，两个字段都要有，别合并。

章节结构：

```
Chapter {
  id, textbookId,
  no,        // 章号，如「第五章」；原文怎么写的就怎么存，不要规范化
  title,     // 章名，如「被子植物」
  sections: [
    { no: '第一节', title: '木兰科' },
    ...
  ]
}
```

**章号与节号存原文写法**（「第五章」而不是 `5`，「第一节」而不是 `1`）。
理由：老师口头说的是"第五章"，教材上印的也是"第五章"，规范化成数字反而要多一层转换，还可能把"上篇/下篇"这种结构搞丢。

#### 二、目录录入（关键：三种来源，都不许模型编）

按可靠性排序，界面上都提供：

**A. 手动录入**（最可靠）
逐条添加章和节。麻烦但绝对准确。

**B. 粘贴目录文本 → 结构化**
用户从电子版目录、豆瓣读书、出版社官网复制一段目录文本，比如：

```
第五章 被子植物
  第一节 木兰科
  第二节 蔷薇科
  第三节 豆科
第六章 单子叶植物
  第一节 禾本科
```

程序把它解析成 Chapter 列表。解析用规则 + 模型兜底：
- 先试正则（`第[一二三四五六七八九十百]+章`、`第[一二三四五六七八九十百]+节`、数字编号）
- 正则搞不定的再交给模型做结构化
- **模型只能重排用户给的文字，不许新增任何章节**

**C. 拍照 OCR**（可选，第二版再做）
需要 OCR 能力。第一版不做，别为它引入原生依赖。

界面必须显示目录来源（手动 / 粘贴 / 未录入），用户能一眼看出数据可信度。

#### 三、课前定位（这是用户最关心的动线）

录音页的流程要变成：

```
打开录音页
  ↓
【第一步：定位置】课程 → 教材 → 章 → 节     ← 新增
  ↓
（可选）预习：显示该章节的历史笔记 / 相关 wiki 词条 / 上次讲到哪
  ↓
【第二步：录音】
```

具体要求：
- 课程选定后，自动带出该课程的教材（`textbookOf` 已有的模糊匹配）
- 教材可以换（用户可能用不同版本）
- 章、节从该教材的目录里选；目录为空时提示「先录入目录」，并提供跳转
- **允许跳过**：不想填就不填，直接录音。这时候行为要和现在完全一致（不能因为没选章节就录不了）
- 选完之后界面顶部常驻显示当前位置，如「植物学（第三版）· 第五章 被子植物 · 第二节 木兰科」

#### 四、把位置喂给下游（这是这个功能的价值所在）

选定章节后，五处要接上：

| 环节 | 现在 | 接上之后 |
|---|---|---|
| 术语表生成 | `prepare(courseName)`，章节为空 | `prepare(courseName, topic: '第五章 被子植物 第二节 木兰科', material: '植物学（第三版）方炎明 中国林业出版社')` |
| 纠错 | 按课程+空章节查缓存 | 按课程+真实章节查缓存，命中率高得多 |
| 总结 | 提示词里只带教材书名 | 提示词里带完整位置，模型知道"这节该讲什么" |
| Wiki 归类 | 只按课程 | 词条可以带章节出处，能看出"这个词是第五章讲的" |
| RAG 检索 | 全库检索 | 可按章节过滤，搜"木兰科"能限定在这一节 |

**特别注意术语表这一条**：现在术语表是录音后生成的，用一次调用的钱。如果在录音前定位了章节，可以**在录音前就把术语表准备好**——这样纠错时直接命中缓存，省一次调用，而且术语更贴合本节内容。

#### 五、笔记落库

`notes` 表要能记住这次录音对应的位置：

- `textbook_id`（可为空）
- `chapter_no`（原文写法，如「第五章」）
- `chapter_title`（如「被子植物」）
- `section_no`（如「第二节」）
- `section_title`（如「木兰科」）

存 `no` 与 `title` 分开，不合并成「第五章 被子植物」一个字符串——
将来要按章分组、按节排序都得靠结构化字段。

老笔记这些字段为空，读的时候不显示位置即可，不要迁移数据。

### 技术判断与风险

1. **目录解析不要过度依赖模型。**
   正则能覆盖「第五章 / 第一节 / 5.1 / 一、」这几种常见写法，先正则后模型。
   模型只在正则失败时兜底，且必须回传"我只重排了你给的文字"的保证——
   实现上更简单的做法是：**模型输出的每一行都必须在用户输入里能找到**，
   找不到的行直接丢弃并在界面上提示「丢弃了 N 行无法对应的内容」。
   这是可验证的防编造手段，比在提示词里写"不要编造"可靠得多。

2. **教材目录可能很长。**
   植物学教材可能有十几章上百节。列表要用折叠式（章展开才显示节），
   不要一次铺开几百行。

3. **章节选择必须可跳过。**
   上课时用户可能赶时间，不想每次都选。跳过时行为要与现在完全一致。

4. **术语表预生成要考虑失败。**
   课前生成术语表要调模型，可能失败（没网、Key 没配）。
   失败不能阻断录音——降级为"录音后照旧生成"。

5. **`dbVersion` 现在是 7，本次会到 8（或 9）。**
   每个迁移分支独立且可重入，用 `IF NOT EXISTS` / `_addColumnIfMissing`。

6. **测试环境限制**：
   - `DbService` 是单例，测试间会串数据，已有注入点：
     `DbService.factoryOverrideForTest` / `dbPathOverrideForTest` / `resetForTest()`
   - 真实 API 测试要 `apiKeyOverride` 注入 Key，否则读不到 SharedPreferences
   - `sqflite_common_ffi` 可在桌面跑真实 SQL 测试，已验证可用

7. **构建环境**（不设就是一堆莫名错误）：
   ```bash
   export JAVA_HOME="/e/dev/jdk-21.0.13+9"
   export ANDROID_HOME="/e/dev/android-sdk"
   export ANDROID_SDK_ROOT="$ANDROID_HOME"
   export PATH="$JAVA_HOME/bin:$PATH"
   export PUB_HOSTED_URL=https://pub.flutter-io.cn
   export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
   export PUB_CACHE=/e/dev/pub-cache   # 必须 ASCII 路径
   ```
   验证签名要用 Windows 风格 `JAVA_HOME="E:/dev/jdk-21.0.13+9"`。
