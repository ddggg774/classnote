## 零、读代码发现的两个前置缺口（不先解决，后面四项都会返工）

### 缺口 1：笔记没有结构化的「课程」字段

**现状**：`Note.title` 的注释写着「课程名」，实际上它是用户在录音页随手填的标题。所有需要「课程」的地方都在拿 title 顶替：

```dart
// record_page.dart:281
courseName: title,
// note_detail_page.dart:176
courseName: _note!.title,
```

`AppConfig.textbookOf()` 用 `contains` 模糊匹配教材，所以标题写成「植物学第三讲」能命中，写成「第三讲」就匹配不到——教材注入、术语表检索、模板匹配全部落空。

**影响**：模板按课程匹配（第 1 项）、Wiki 按课程组织词条（第 3 项）、RAG 按课程过滤（第 2 项）**全都依赖准确的课程归属**。

**改法**：`notes` 表加 `course TEXT` 字段（可空，空则回退用 title）。录音页把标题输入框拆成「课程选择器 + 标题」，课程列表来自 `AppConfig.textbooks` 的 3 本 + 用户自定义。

---

### 缺口 2：FTS5 在 Android 上不能假设可用

**现状**：完全没有检索能力。

**风险**：`sqflite` 走的是 Android 系统自带的 SQLite。FTS5 需要编译时启用 `SQLITE_ENABLE_FTS5`——AOSP 从 API 26 起默认开启，但**厂商定制 ROM 会裁剪**。这不是理论风险，是「在某些设备上直接建表失败」。

**结论**：RAG 第一版**不赌 FTS5**，用普通表自建 bigram 倒排索引（纯 SQL，100% 可用）。同时做运行时探测，如果设备支持 FTS5 就走快路径。

理由：倒排索引的查询逻辑我能完全掌控（BM25 排序、高亮、按字段加权都能自己实现），而 FTS5 一旦不可用就是整条链路崩掉。体积估算：5000 字笔记去重后约 2000-3000 个独特 bigram，100 篇笔记 20-30 万行，SQLite 毫无压力。

## 一、五项能力改造点

### 第 1 项：模板整理

**现状**：`ai_service.dart` 里三个常量 `_detailSystemPrompt`（九段式）/ `_chunkSystemPrompt`（分块）/ `_mergeSystemPrompt`（合并）。`buildPromptForLevel()` 用 `switch` 在 brief/normal/detail 之间选择或做 `replaceFirst` 插入额外要求。

**关键发现**：`_detailSystemPrompt` 内部混了三类东西，必须拆开：

| 层级 | 内容 | 模板能不能改 |
|---|---|---|
| 通用铁律 | 绝不能编造 / 标〔待确认〕/ 保留公式原样 / 不凑结构 | ❌ 所有模板共用 |
| 整理要求 | 去口语重复 / 书面语重述不改原意 / 逻辑关系 / 来源标签 | ❌ 所有模板共用 |
| **输出结构（9 节）** | `# 课程信息` `# 知识点结构` ... `# 时间戳回溯` | ✅ **这才是模板变量** |
| 导图 JSON 规范 | 11 个固定一级分支 / 3-5 层 / relation / mark | ⚠️ 见下方决策点 1 |

**改法**：
- 抽出 `NoteTemplate` 模型：`id / name / scene / course / sections[] / mindmapBranches? / builtin`
- `sections[]` 每项：`title / required / requirements[]（该节的写作要求）/ needQuote(是否强制带原文引用) / needTable`
- 新增 `lib/services/template_service.dart`：内置模板注册 + 按课程匹配 + 自定义模板 CRUD
- `AiService.buildPromptForLevel(level, courseName)` → `buildPrompt(template, level, courseName)`
- 落库：`notes` 记 `template_id`，详情页可切换模板重新生成

**内置模板（4 个）**：
1. `builtin-general` 九段式（现有，默认）
2. `builtin-brief` 速览（现有 brief 档那三节）
3. `builtin-lab` 实验/实习报告：实验目的 / 材料与仪器 / 方法与步骤 / 结果记录 / 讨论与分析 / 结论 / 安全与注意事项
4. `builtin-drawing` 制图与规范：图纸类型与图名 / 图幅与比例 / 线型与线宽 / 尺寸标注规则 / 投影与视图关系 / 常见错误 / 作业要求 —— 专为建筑制图、园林制图

**涉及文件**：
- 新增：`lib/models/note_template.dart`、`lib/services/template_service.dart`
- 修改：`lib/services/ai_service.dart`（拆 prompt）、`lib/services/db_service.dart`（v5）、`lib/models/note.dart`（+course +templateId）、`lib/pages/record_page.dart`（课程选择器）、`lib/pages/note_detail_page.dart`（模板切换）、`lib/pages/settings_page.dart`（自定义模板入口）

**验收**：同一段转写用实验报告模板与九段式模板，产出章节结构明显不同；植物学默认九段式、制图课默认制图模板；自定义模板存得进读得出；`prompt_build_test.dart` 15 个用例不回归。

### 第 2 项：RAG 检索

**现状**：零检索。首页只有一个笔记列表。

**改法（分两步，第一步就能用）**：

**第一版：自建 bigram 倒排索引**
- 建表 `search_terms(term, note_id, field, weight)`，`term` 是 bigram
- 中文切 bigram：「木兰科」→「木兰」「兰科」。英文/数字按词切（连续 `[a-zA-Z0-9]+` 整词 + 前缀）
- 索引来源三个字段：title（权重 3）/ transcript（权重 1）/ summary（权重 2）
- 查询：把 query 同样切 bigram，`WHERE term IN (...)` 统计命中数，按 `命中数 × 字段权重 / 文档长度` 排序（简化 BM25）
- 高亮：拿到 note_id 后回原文 `indexOf` 定位（复用 `pending_fixer.dart` 里已有的定位思路）
- 索引同步：`insert/update/delete` 笔记时增量更新；提供「重建全部索引」按钮兜底

**第二版（可选增强）：embedding 精排**
- 复用硅基流动 Key，调 embedding 接口
- 向量存 SQLite（BLOB），朴素 cosine（笔记量小，不需要 FAISS/annoy）
- **不用 sqlite-vec**（原生扩展，风险同 RNNoise）

**跨笔记问答**：检索 top-N 片段 → 喂给 LLM（新提示词：只根据给定片段回答，找不到就说找不到，必须带出处 `[笔记标题 @ 时间]`）

**涉及文件**：
- 新增：`lib/services/search_index.dart`、`lib/services/rag_service.dart`、`lib/pages/search_page.dart`
- 修改：`db_service.dart`（v6）、`home_page.dart`（搜索入口）、`ai_service.dart`（问答提示词）

**验收**：搜「木兰科」能列出所有相关笔记并高亮；搜「离生心皮」能部分命中原文写成「离心皮」的段落；跨笔记问答给带出处答案；笔记增删改后索引一致（用测试锁住）。

### 第 3 项：LLM Wiki

**现状**：只有按「课程+章节」缓存的术语表（`terminology_cache`）。笔记之间完全孤立。

**改法**：
- 建表 `wiki_entries`（id/course/term/type/definition/variants_json/related_json/created_at/updated_at，`UNIQUE(course, term)`）+ `wiki_sources`（entry_id/note_id/snippet/conflict）
- `type` 枚举：术语 / 人物 / 公式 / 概念 / 易错点 / 例题套路
- **增量抽取**：笔记落库后，抽取候选词条 → 与已有比对：
  - 新词条 → 新建
  - 已存在且定义兼容 → 追加 source（不覆盖定义）
  - 已存在但定义冲突 → **保留双版本**，两个 source 都标 `conflict=1`，界面提示「待核对」
- **幂等**：同一笔记重复抽取不产生重复词条（用 `(course,term)` 唯一约束 + source 去重）
- 浏览界面：按课程分组 / 按 type 筛选 / 搜索 / 点词条看定义 + 全部出处（可跳回原文）
- 与术语表打通：Wiki 的 `variants` 喂给识别 Agent 的 `lookup_terminology`

**涉及文件**：
- 新增：`lib/models/wiki_entry.dart`、`lib/services/wiki_service.dart`、`lib/pages/wiki_page.dart`、`lib/pages/wiki_entry_page.dart`
- 修改：`db_service.dart`（v7）、`correction_agent.dart`（术语检索扩展）、`home_page.dart`（Wiki 入口）

**验收**：连续处理 3 节植物学课后有 20+ 词条，每条能追溯到具体某节课原文；同一术语两节课定义不同时双版本都保留、都标出处、界面提示冲突；重复抽取同一笔记不产生重复词条。

### 第 4 项：画布

**现状**：`mind_graph_tree.dart` 是「`MindGraphOverview` 主图（11 个分支横向卡片）+ `MindGraphSubtree` 可折叠树」。看不到全局，不能缩放平移。

**改法**：
- 新增真正的 2D 画布：`CustomPaint` 绘制 + `Matrix4` 手势变换
- **不用 `InteractiveViewer`**：它会和节点拖拽抢手势，实测容易出「想拖节点结果整图跑了」
- 布局算法：层次树布局（Reingold-Tilford 简化版）——一级分支水平排开、子节点垂直递归展开、同层节点垂直居中于子节点
- 性能（目标 11 分支 40+ 节点流畅）：
  - `RepaintBoundary` 隔离画布
  - 节点文本用 `TextPainter` 预计算并缓存（缩放时不重新排版）
  - 只绘制视口内节点（简单裁剪）
  - 缩放用 `Matrix4` 整体变换，不逐个重算坐标
- 交互：双指缩放 / 单指拖空白平移 / 拖节点移动（重排到最近父节点）/ 点节点展开详情
- 保留现有树视图（屏幕小时树更好用），画布与树可切换
- 导出：画布内容渲染成 PNG（注意 `pixelRatio` 与内存上限，现有 `mind_map_widget.dart` 的做法可参考）

**涉及文件**：
- 新增：`lib/widgets/graph_canvas.dart`、`lib/services/tree_layout.dart`（布局算法，纯函数好测）
- 修改：`lib/pages/note_detail_page.dart`（思维导图 Tab 加视图切换）

**验收**：11 分支 40+ 节点完整显示、缩放平移跟手；拖节点不触发画布平移；缩放后文字清晰（非位图拉伸）；树与画布切换数据一致；导出 PNG 与原图一致。

### 第 5 项：Skills

**现状**：`classroom_agent.dart` 的 `_buildTools()` 硬编码四个工具（transcribe / run_correction_agent / summarize / generate_mindmap），「一键处理」固定跑这套。

**改法（内部 Skills，不做真 MCP）**：
- `Skill` 模型：`id / name / description / enabled / tools[] / promptKey / applicableCourses[]`
- `SkillRegistry`：内置 5 个技能
  - `term-fix` 术语纠错
  - `summary-normal` 九段式总结
  - `summary-brief` 速览总结
  - `exam-points` 提取考点清单（新）
  - `quiz` 生成复习题（新）
- **动态组装**：`ClassroomAgent` 的工具集从 `SkillRegistry.enabledSkills` 来，不再硬编码
- `SkillProvider` 抽象：`Future<List<Skill>> skillsFor(course)` —— 将来接 MCP server 时实现这个接口即可，业务层不动
- 设置页：技能启停开关
- 「一键处理」的运行步骤随启用技能变化

**涉及文件**：
- 新增：`lib/models/skill.dart`、`lib/services/skill_registry.dart`、`lib/services/skill_provider.dart`（抽象）
- 修改：`classroom_agent.dart`（动态组装）、`agent_run_sheet.dart`（步骤标签动态）、`settings_page.dart`、`db_service.dart`（v8，存技能启停配置）

**验收**：3+ 技能可独立启停；关掉总结就真的不调 summarize（不是假开关）；加新技能只改一个文件；`SkillProvider` 抽象存在且有内部实现。

## 四、风险点

| 风险 | 影响 | 应对 |
|---|---|---|
| FTS5 在部分 ROM 不可用 | 检索整条链路崩 | 第一版就用自建倒排表，FTS5 只作可选快路径 |
| bigram 索引体积膨胀 | 数据库变大 | 去重 + 只索引三个字段 + 提供重建入口；估算 100 篇约 20-30 万行，可控 |
| 画布手势冲突 | 拖节点变成拖画布 | 不用 InteractiveViewer，自己算命中；节点矩形先判定，命中则拦截 |
| 画布性能 | 大图卡顿 | TextPainter 缓存 + 视口裁剪 + RepaintBoundary |
| 模板改动破坏现有 prompt | 总结质量下降 | 拆 prompt 时保留原文铁律一字不改，只把 9 节抽走；用 `prompt_build_test` 锁住 |
| Wiki 抽取编造 | 知识库被污染 | 沿用纠错层的铁律：只抽原文有的，拿不准标待确认；抽取结果给用户确认后才入正式库 |
| 课程字段与标题不一致 | 老的笔记没有 course | 迁移时 `course` 留空，回退用 title；界面上提示用户补全 |
| 每阶段的 DB 版本递增 | 用户跨版本升级出问题 | 每版本分支独立且 `IF NOT EXISTS` / `_addColumnIfMissing` 保证可重入 |

## 五、需要你拍板的 5 个决策点

这两个我倾向的方案已写在括号里，你直接说「都按你说的」也行。

**1. 导图一级分支跟不跟模板走？**
- 选项 A：固定 11 个分支不变（模板只管正文）——改动小，`mind_graph_test.dart` 17 个用例不动
- 选项 B：分支跟着模板走——一致性好，但要改 `MindGraph.requiredBranches` 与相关测试
- （我倾向 **A + 模板可选覆盖**：默认固定 11 个，模板可声明 `mindmapBranches` 覆盖，向后兼容）

**2. RAG 第一版要不要直接上 embedding？**
- 选项 A：先纯 bigram 关键词检索（零成本、当天可用）
- 选项 B：直接 bigram + embedding 混合（效果更好，但每篇笔记要多一次 embedding 调用）
- （我倾向 **A 先跑通，B 作为增强**——先看到效果再决定要不要花这个钱）

**3. 课程名怎么定？**
- 选项 A：录音页让用户从列表选（`植物学` / `建筑制图` / `园林制图` / 自定义），标题单独填
- 选项 B：保持现在这样标题即课程，靠模糊匹配
- （我倾向 **A**——这是第 1、2、3 项的公共前置，不做会一直别扭）

**4. Wiki 抽取什么时候触发？**
- 选项 A：笔记落库后自动抽取（无感，但每篇多一次 LLM 调用）
- 选项 B：用户在笔记页点「加入知识库」才抽（可控，能避免把噪音笔记污染知识库）
- 选项 C：两者都有，设置里开关
- （我倾向 **C**：默认自动，可关，且抽取结果先进「待确认」区，用户确认后才入正式库）

**5. 画布与树视图的关系？**
- 选项 A：并存，可切换（我倾向这个）
- 选项 B：画布完全替换树
